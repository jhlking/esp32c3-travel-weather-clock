# KairosTide：借鉴一点思路，做自己的二次开发与创作

## 关系定位

**被借鉴的项目**：立创开源硬件平台「旅行天气时钟-Esp32C3 2.0」（作者 eda_pnhleoqpu，GPL 3.0）——一块 ESP32-C3 + 1.9 寸 LCD 的桌面天气时钟，显示时间、日期、天气与温度，带万年历、商店、花园和自定义铃声。

**KairosTide**：只借鉴了这个项目的少量思路，并在此基础上做了大幅二次开发与原创创作。我们没有沿用它的硬件设计、结构或固件；产品定义、交互方式、助手系统、场景渲染与软件架构都是自己做的。

一句话区分：**被借鉴的项目把时间显示出来；KairosTide 让时间可以被感知，但不被盯着。**

## 我们借鉴了什么

只有三件事：

1. **场景方向**：桌面上的设备可以是一件呈现天气与时间氛围的物品，而不只是工具。
2. **数据入画**：天气、日期、温度这些真实世界信息可以进入画面，而不是只存在于列表里。
3. **开源精神**：低成本、可复刻、公开分享的做法值得我们尊重，也促成我们把原项目资料整理归档、注明出处。

仅此而已。硬件电路、外壳结构、BOM 与原固件都不在我们的创作范围内，知识产权仍归原作者。

## 我们的二次开发与原创创作

### 1. 产品哲学：从“读时间”改为“感知时间”

被借鉴的项目是“时钟”：时间常驻屏幕，用户随时读到几点几分。KairosTide 刻意反过来——首页是田园四时场景，**平时不显示钟点、时间轴、下一事件或剩余分钟数**。时间藏在太阳高度、天空颜色、月相、云影、水面和物候里。想确认时间就长按画面约 600ms，在按压点附近显示真实时间，约 3 秒后淡出；想看安排就开口问助手。两件事都不占屏幕。

这是产品定义层面的原创，不是界面样式调整。

### 2. 物候生灵提醒

事件进行中，池塘上出现一只属于当时季节、时段与天气的动物（野鸭、蝴蝶、蜻蜓、白鹭、青蛙、萤火虫、白鹤），点它展开事件卡；事件结束或记为例外后散场。生灵与画面里原本就在飞的蝴蝶、亮着的萤火虫共用一套物候模型，提醒不打断田园画面。

被借鉴的项目用蜂鸣器和屏幕弹窗提醒；我们用“场景里多了一只生灵”代替圆环、红点和倒计时。

### 3. 对话助手 Kairos：只出草稿，不替用户决定

助手用自然语言查日程、查天气，把用户说的话整理成**待确认草稿**，确认后才写入日程。规则是原创的核心：

| 规则 | 含义 |
| --- | --- |
| 草稿不是日程 | 必须点“确认保存 / 修改 / 删除 / 请假”才生效 |
| 不猜 | 时刻、时长、标题、地点没说就不填，改为提问 |
| 不编造依据 | 每份草稿都引用用户原话，服务端逐字核对 |
| 否定或假设不执行 | “别加了”“如果我要……”不会触发写入 |
| 冲突由用户选 | 只说明重叠了哪一条，由用户自己选保留哪条 |
| 图片不作留档 | 图片只随当轮请求发给模型，不进数据库、不进历史 |

同时支持柔性任务（背单词、写实验报告这类“抽空完成”的事）和图片导入课表/通知生成可勾选草稿。模型只负责理解，**服务端负责拒绝**，这条边界是我们自己定的。

### 4. 真实世界数据驱动的场景

不是静态壁纸，也不是随机动画：

- 时间、地点与真实天气决定首页画面；拒绝定位后按时区估算继续运行。
- 真实亮星表、月相与月距、流星雨历表、农历与节气进入场景与时间文案。
- 锦鲤的体轴行波游动、萤火虫的脉冲耦合同步、树木的悬臂梁摆动与冠层光斑，均按可查证的文献模型实现。

被借鉴的项目展示“今天的天气”；我们让天气、天文与物候共同决定“此刻的世界是什么样”。

### 5. 软件架构与工程规范

- 分层固定为 `api → application → domain`，领域层是纯逻辑；端口放在应用层，适配器实现外部依赖。
- 三种时钟分离：`RealClock`、`SceneClock`、`ScheduleClock`。
- 契约先行：`openapi.json` 生成前端 `api.d.ts`，改动后必须重新生成。
- 门禁统一入口 `scripts/check.py all`：文档链接、分层依赖、单文件 ≤400 行、mypy strict、ruff、pytest、vue-tsc、vitest、构建。
- 隐私随用随弃：密钥只在服务端，图片字节不落库。

这些是 KairosTide 自己的工程资产，与被借鉴的硬件工程没有继承关系。
